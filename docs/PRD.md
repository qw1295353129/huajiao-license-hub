# LicenseHub 产品需求文档（PRD）

## 1. 定位

给 **一个人运营的软件生意** 用的授权中台。你要把软件卖给别人（一次性买断、订阅、时长卡、试用转正），
就需要一个地方回答四个问题：

1. **谁** 有权使用我的软件？（发码 / 授权）
2. 他现在 **还有效吗**？（校验 / 心跳 / 到期）
3. 他在 **几台机器** 上用？（设备绑定 / 解绑）
4. 我 **赚了多少、跑掉多少**？（订单 / 激活数据 / 异常）

LicenseHub 就是这四个问题的答案，且数据 100% 在你自己机器上。

## 2. 角色

| 角色 | 说明 | 入口 |
| --- | --- | --- |
| 运营者（owner） | 你自己，全部权限 | `/admin` |
| 协作者（admin / support / readonly） | 客服、只读财务等，按角色收敛权限 | `/admin` |
| 终端用户（customer） | 买家，自助查授权、解绑设备、看订单、兑换卡密 | `/portal` |
| 接入应用（client app） | 你自己的软件，通过 API Key 调用激活/校验接口 | `/api/v1` |

## 3. 功能清单

### 3.1 产品与版本（Products & Releases）
- 产品 CRUD：名称、slug、描述、Logo、官网、状态（草稿/上架/归档）
- 版本发布记录（版本号、渠道 stable/beta、更新说明、下载地址）
- 功能点（feature key）定义：授权可按功能点下发，实现"基础版/专业版"差异
- 多产品并存：一套系统运营多个软件

### 3.2 授权策略（Plans）
- 授权类型：**试用 trial / 订阅 subscription / 永久 perpetual / 时长卡 duration / 次数卡 consumable**
- 策略字段：有效期天数、最大设备数、离线宽限天数、心跳间隔、功能点集合、是否需人工审批设备
- 一个产品多套策略（个人版/专业版/团队版），策略可复制

### 3.3 授权码（Licenses）
- 生成：格式可配（分组长度、字符集、前缀），单条 / 批量 N 条 / CSV 导入
- 存储安全：明文 **不落库**——AES-256-GCM 密文 + HMAC 盲索引（可查不可读），列表只显示掩码
- 状态机：`issued → active → expired / suspended / revoked / banned`，任意状态可手工流转
- 批量操作：吊销、暂停、恢复、延期、换绑、导出 CSV
- 归属：可绑定客户邮箱，也可匿名发放（后续再绑定）
- 备注与元数据（订单号、渠道、来源）

### 3.4 激活与校验 API（客户端接入面）
- `POST /api/v1/activate`：授权码 + 设备指纹 → 返回 **Ed25519 签名的授权文件** + 短期 access token
- `POST /api/v1/verify`：心跳续期，返回最新权益（到期时间、功能点、剩余次数）
- `POST /api/v1/deactivate`：释放一个设备名额
- `POST /api/v1/trial`：按设备指纹发放试用，同设备同产品仅一次（防刷）
- **离线激活**：request code → 运营者后台生成 response code → 客户端离线写入授权文件（内网/无网环境）
- 公钥分发：`GET /api/v1/public-key`，客户端本地验签，无需信任网络

### 3.5 设备管理（Devices）
- 设备指纹、名称、操作系统、IP、首次/最近出现时间
- 设备数超限策略：拒绝新设备 / 自动踢掉最久未使用设备
- 用户自助解绑（每月限次，防共享账号）+ 管理员强制解绑
- 硬件黑名单（封禁指纹，全产品生效）

### 3.6 客户与门户（Customers & Portal）
- 客户注册/登录/找回密码（邮箱验证）
- 自助门户：我的授权、剩余天数、设备列表与解绑、订单与发票、卡密兑换、下载
- 管理员可重置客户密码、封禁客户

### 3.7 订单与支付（Orders）
- 商品（产品 + 策略 + 价格 + 周期）、下单、待支付、已支付、已退款、已取消
- 支付提供方 **可插拔**：`manual`（线下收款手工确认）、`redeem`（卡密）、`stripe`、`webhook`（对接爱发电/发卡网等）
- 支付成功 → 自动发码 → 自动邮件（幂等，重放安全）
- 退款 → 自动吊销关联授权（可配置是否回收）

### 3.8 卡密与兑换（Redeem Codes）
- 批量生成卡密（淘宝/闲鱼/发卡网渠道），导出 CSV，作废未使用卡密
- 批次管理，可绑定策略与有效期
- 用户在门户兑换 → 生成正式授权

### 3.9 优惠券（Coupons）
- 百分比 / 固定金额、限次、限时、限产品

### 3.10 通知（Notifications）
- 邮件模板：欢迎、发码、授权到期提醒（T-7/T-3/T-1）、异常登录、设备解绑
- SMTP 配置后台可改；开发环境用日志传输，不误发邮件
- Webhook 事件推送：license.created / activated / expired / revoked、device.bound / unbound、order.paid

### 3.11 开放 API 与 Webhook
- API Key 管理：名称、作用域、绑定产品、最后使用时间、吊销
- Webhook 签名投递（HMAC-SHA256 + 时间戳防重放）、失败指数退避重试、投递日志可查可重放

### 3.12 审计与安全
- 全量审计日志：谁、何时、对什么、改了什么（含 diff）、IP、UA
- 管理员登录：密码 + **TOTP 双因素**、登录失败锁定、会话管理（可踢下线）
- RBAC：owner / admin / support / readonly
- 限流：登录、激活、校验分别限流；敏感操作二次确认

### 3.13 数据看板（Dashboard）
- KPI：总授权、活跃授权、今日激活、7 日新增、到期预警、试用转化率
- 趋势图：激活/校验/新增授权时间序列
- 分布：产品、平台（Win/macOS/Linux）、地域
- 异常面板：同一授权多设备、校验失败激增、黑名单命中

### 3.14 系统设置
- 站点名称/Logo/主题色、时区、是否开放客户注册
- 邮件、Webhook、限流参数
- **签名密钥管理**：生成、查看公钥、轮换（kid 保留旧公钥，老授权文件仍可验签）

## 4. 补充建议（"还有什么要补充的"）

按 **性价比** 排序，建议全部纳入首个可用版本：

| # | 补充项 | 为什么个人运营必须有 |
| --- | --- | --- |
| 1 | **离线激活 + 本地验签** | 你的用户可能在无网/内网环境；Ed25519 签名让客户端不联网也能判有效性 |
| 2 | **授权码不可逆存储 + 掩码展示** | 数据库被拖库 ≠ 授权码泄露；这是授权系统最容易翻车的地方 |
| 3 | **设备指纹 + 解绑配额** | 直接决定"一码多机"能不能防住；自助解绑降低你的客服成本 |
| 4 | **试用防刷** | 试用是最容易被薅的入口，按设备指纹 + 邮箱双维度限制 |
| 5 | **到期提醒邮件** | 续费转化的主要来源，纯自动，写好模板就躺着收钱 |
| 6 | **卡密体系** | 国内个人开发者主要走淘宝/闲鱼/发卡网，卡密是刚需 |
| 7 | **Webhook** | 让授权系统和你的其它工具（飞书/钉钉/自建脚本）打通 |
| 8 | **审计日志** | 出问题时能复盘：谁把这条授权删了 |
| 9 | **TOTP 双因素** | 后台能发码=能印钱，账号被盗损失直接 |
| 10 | **签名密钥轮换** | 私钥泄漏时可平滑换钥，不清空历史授权 |
| 11 | **异常检测面板** | 授权异常（多地同时在线、暴力试码）自动浮出 |
| 12 | **数据导出与备份** | 个人运营没有 DBA，一键导出 + 备份脚本 |
| 13 | **客户自助门户** | 让用户自己解决 80% 的"我换电脑了"问题 |
| 14 | **多产品/多渠道标记** | 一个人往往不止卖一个软件 |
| 15 | **速率限制与防爆破** | 授权码是短字符串，必须防枚举 |

**明确不做（非目标）**：多租户 SaaS、复杂 ERP 财务、发票税务对接、客户端反调试/加壳（属于客户端保护范畴，只提供验签与心跳机制）。

## 5. 成功标准

- 单个 Docker 主机（2C4G）可跑，冷启动 < 30s
- 能完整走通：上架产品 → 建策略 → 生成卡密 → 用户兑换 → 客户端激活 → 心跳续期 → 到期提醒 → 续费延期 → 退款吊销
- 授权码泄露风险：库中无明文，接口返回掩码，仅创建时可复制一次
- 所有管理端写操作可在审计日志中回溯
